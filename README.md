# Adrobot — обёртка над Keitaro

Создание кампаний и редактор офферов на **FastAPI + SQLAlchemy 2 + SQLite**.
Интерфейс на HTML, CSS и JavaScript обслуживается тем же приложением.
Для фронтенда не нужны Node.js и сборка.

## Запуск

Нужен Python **3.12**. Все команды выполняются из корня репозитория.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В Windows вместо `source` выполните `.venv\Scripts\activate`.

Заполните `.env` своими значениями.

```dotenv
KEITARO_URL=https://your-tracker.example
KEITARO_API_KEY=your-api-key
DATABASE_URL=sqlite:///./adrobot.db
CAMPAIGN_PREFIX=test_tyutikov_
REPORT_TIMEZONE=Europe/Moscow
```

`KEITARO_URL` — HTTPS-адрес трекера без `/admin`. Ключ можно скопировать
в Keitaro из раздела «Профиль → API ключи». Он используется только на сервере.
Рабочие ключи, пароли и база данных исключены из Git.

Примените миграции и запустите приложение.

```bash
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [интерфейс](http://127.0.0.1:8000) или
[Swagger приложения](http://127.0.0.1:8000/docs).
Приложение рассчитано на локальный запуск доверенным пользователем.
Для общего доступа потребуются аутентификация и HTTPS перед приложением.

## Создание кампании

1. Введите название с префиксом `test_tyutikov_`, например
   `test_tyutikov_campaign1`.
2. Укажите ISO-коды стран, например `AU` или `AU, MX, RO`.
3. Выберите оффер из подсказок по названию либо введите его ID.
4. Выберите домен, группу и источник из Keitaro. Если доступны, группа
   и источник `FORTESTS` выбираются автоматически.
5. Нажмите «Создать кампанию».

Кампания использует ротацию по позиции и два потока.

- **Flow 1 · Google** — обычный поток на первой позиции. Фильтр `country`
  принимает указанные страны, HTTP-редирект ведёт на `https://google.com`.
- **Flow 2 · Offers** — замыкающий поток типа `default`. Остальные посетители
  отправляются на выбранный оффер с долей 100%.

Кампания создаётся выключенной и включается после настройки обоих потоков.
Каждой попытке соответствует `request_id`, который сохраняется в SQLite.
При сетевой ошибке повторите создание с теми же параметрами в той же вкладке.
Браузер сохраняет идентификатор незавершённой попытки в `sessionStorage`.
После перезагрузки страницы восстанавливаются и поля формы.

Через API можно повторить `POST /api/campaigns` с прежним `request_id`.
Сервер продолжит настройку существующей кампании. Детерминированный alias
позволяет найти её даже при потере ответа на первый POST.
Завершённый запрос возвращает прежний ID.
Если данные запроса изменились, используйте новый UUID.

## Редактор

Введите ID существующей кампании либо выберите её в подсказках.
Загрузятся все её потоки и сохранённые локальные черновики.

- «Добавить оффер» добавляет существующий активный оффер Keitaro.
- «Удалить» исключает оффер из распределения. Он доступен через
  «Показать удалённые» и кнопку «Вернуть».
- «Закрепить» фиксирует введённый процент. Оставшийся трафик поровну
  распределяется между незакреплёнными офферами.
- «Открепить» возвращает оффер в автоматическое распределение.
- «Сохранить в Keitaro» отправляет изменения конкретного потока.
- «Отменить / обновить» сбрасывает черновик, удалённые строки и закрепления,
  затем заново читает поток из Keitaro.
- «Загрузить потоки» перечитывает кампанию, сохраняя локальные черновики.
  Внешние изменения отмечаются предупреждением.

Доли — целые проценты с суммой 100. Остаток получают первые
незакреплённые строки. Например, для трёх офферов это 34/33/33,
а при закреплении одного на 25% — 25/38/37.
Нельзя удалить последний активный оффер или задать несовместимые закрепления.
Изменение процента применяется кнопкой «Закрепить».
Удалённые офферы сохраняются в локальном черновике после отправки,
чтобы их можно было вернуть.

Черновики и закрепления хранятся в SQLite и переживают перезапуск сервера.
До сохранения изменения не отправляются в Keitaro.
На отправку уходит только список офферов выбранного потока.
Перед этим сервер сравнивает поток с загруженной версией.
Конфликт с внешним изменением возвращает HTTP 409.
Ревизия черновика защищает от перезаписи из устаревшей вкладки,
а транзакция SQLite сериализует изменения между процессами.

Keitaro API не предоставляет условный PUT с версией потока.
Поэтому внешнее изменение между проверкой и отправкой остаётся возможным.
После отправки приложение повторно читает результат и проверяет доли.
При потере ответа черновик сохраняется. Повторное сохранение распознаёт
уже применённый список офферов.

## Статистика

Цифры берутся из `POST /admin_api/v1/report/build` с фильтром по кампании
и группировкой по потоку и офферу. Показываются клики, конверсии,
доход, расход, прибыль и ROI за текущий день в `REPORT_TIMEZONE`.
Денежные значения возвращаются в валюте отчёта Keitaro.
Мини-график показывает клики по дням за последние 7 дней.
Если API статистики недоступен, интерфейс сообщает об ошибке.
Офферы без строк в успешно загруженном отчёте имеют нулевые показатели.

## Миграции

Приложение использует Alembic и не создаёт таблицы автоматически.

```bash
python -m alembic current
python -m alembic upgrade head
python -m alembic downgrade base
```

`downgrade base` удаляет локальные таблицы и черновики.
Кампании в Keitaro остаются доступны в трекере.
Перед откатом сохраните резервную копию файла SQLite.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты используют временную SQLite и подмену API. Проверяются создание двух
потоков, валидация, повтор после потери ответа, расчёт и закрепление долей,
удаление/возврат, отмена, конфликт ревизий, внешние изменения и сбой сохранения.
Для них не нужен доступ к Keitaro.

## Структура

- `app/main.py` — HTTP API, создание кампаний и работа с черновиками.
- `app/keitaro.py` — клиент Admin API с таймаутом и обработкой ошибок.
- `app/models.py`, `app/db.py` — SQLAlchemy и транзакции SQLite.
- `app/shares.py` — распределение долей.
- `app/static/` — интерфейс.
- `migrations/` — миграции Alembic.
- `tests/` — проверки поведения приложения.

Схемы запросов и авторизация сверены с
[официальной документацией Keitaro Admin API](https://admin-api.docs.keitaro.io/).
